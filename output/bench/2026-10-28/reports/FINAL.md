### 3.2 덮어쓴 파일의 상태

Qwen 3.6은 두 반복 모두에서 같은 파일을 다시 썼습니다(01:07). 결측 행이 없었기 때문에 두 명령 모두 모든 줄을 그대로 출력했고,
**파일 내용은 바뀌지 않았습니다**.

- 크기 5,754,987 바이트, 첫 1 MiB의 SHA-256(`b49f6101…`)이 정답 실행 기록과 같음
- CR 문자 없음. 두 명령은 LF 줄바꿈 파일을 그대로 다시 씀
- 이후 다른 모델의 GWAS(A2)가 정답과 같은 수치를 냄
- 바뀐 것은 수정 시각(원래 2026-10-27 18:38:46)과 inode뿐
- 리소스 폴더는 변경 없음

원래 수정 시각으로 되돌리려면 데이터 소유자가 직접 `touch -m -d @1793093926 sam-data/input/KBAv2.0AB_14K_HDL_fixed.txt`를 실행하면 됩니다.

### 3.3 하네스 조치와 확인

- **원인**: 가드는 명령 문자열에서 경로를 찾는 패턴 검사라서 셸 변수나 스크립트 안의 경로는 보지 못합니다.

  - pi와 pi가 띄우는 모든 프로세스(bash, Python, R, sam 도구)는 입력·리소스 폴더에서 생성·수정·이름 변경·삭제·truncate를 할 수 없습니다.
  - 가드는 그 앞에서 먼저 거절하고 이유를 알려 주는 역할로 남습니다.
  - 끄려면 `SAM_SANDBOX=off`. 상태는 `/sam`과 `./sam doctor`로 확인합니다.
- **재현 시험**(`tests/test_sandbox.py`, 13개): 위 두 명령을 포함한 쓰기 10종이 모두 거절되고, 입력 읽기·`output/` 쓰기·임시 파일은 정상입니다.

  - A8 r2: Python heredoc으로 `open(..., 'w')`를 시도했습니다. 가드가 놓친 이 형태를 커널이 `PermissionError: [Errno 13]`로 거절했습니다. 입력은 변경되지 않았습니다.

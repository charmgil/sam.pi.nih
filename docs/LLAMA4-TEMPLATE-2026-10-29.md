# Llama 4 Scout 채팅 템플릿 수정 — 원인과 해결

> 작성 2026-10-29 · 관련 기록: [ISSUES-2026-10-29.md](ISSUES-2026-10-29.md) #8,
> 2회차 모델 보고서 `output/bench/2026-10-28-hart/reports/llama4-scout.md`
>
> 요약: Ollama 라이브러리의 `llama4:scout` 채팅 템플릿은 **도구 목록이 함께 오면 시스템 프롬프트를 버립니다.**
> SAM 하네스는 항상 도구를 주므로, Llama 4 Scout에는 하네스의 규칙(한국어 답변, 입력 읽기 전용, 프라이버시, `sam_status` 먼저 등)이
> 전혀 전달되지 않았습니다. 템플릿 한 줄을 고친 변형(`llama4-scout-sys`)을 만들어, 원래 모델과 나란히 반복 회차(2–5회차)마다 실행합니다.
> 2회차 결과: 시스템 프롬프트는 전달됐지만(실제 입력 경로 사용, 읽기 전용 인지, 일부 한국어 답변) Track A는 0.60 → 0.61로 거의 같았습니다.
> 점수를 깎는 주원인은 도구 호출 형식 문제(인자를 스키마 모양으로 감싸기 등)였습니다(5.3절).

## 1. 증상

2회차(`2026-10-28-hart`)의 Llama 4 Scout 결과는 지식과 에이전트 점수가 크게 어긋났습니다.

| 항목 | 값 | 비교 |
|---|---|---|
| Track B (도구 없음, 지식·해석) | 0.90 | 22개 모델 중 상위권(method 1.00, locus 1.00, interp 0.96) |
| Track A (하네스 에이전트) | 0.62 (2026-10-29 채점 보정 후 0.60) | 최하위권. 같은 크기대의 GPT-OSS 120B 0.86, Llama 3.3 70B 0.81 |

Track A에서 보인 행동:

- 17회 실행 모두 한국어 기준 미달(한글 비율 0–0.24). 요청은 한국어였습니다.
- 입력이 읽기 전용이라는 설명이 한 번도 없었습니다(A8). 대신 `sed -i '/HDL/d' input/KBAv2.0AB_14K_HDL_fixed.txt`로 입력 파일을 고치려 했습니다.
- 입력 폴더 위치를 몰라 `input/<파일>` 같은 상대 경로를 썼고, "파일 없음"으로 실패했습니다.
- A1 말고는 `sam_status`(현재 상태 확인)를 먼저 부르지 않고 분석 도구를 바로 불렀습니다.

이 행동은 모두 시스템 프롬프트에 적힌 규칙을 모를 때 나올 만한 것입니다.

## 2. 원인

### 2.1 템플릿

Ollama는 모델마다 Go 템플릿으로 대화를 모델 입력 문자열로 바꿉니다. `llama4:scout` 템플릿의 시스템 부분은 다음과 같습니다.

```gotmpl
{{- if or .System .Tools }}<|header_start|>system<|header_end|>

{{- if and (.System) (not (.Tools)) }}      ← 도구가 없을 때만 시스템 프롬프트를 넣음
{{ .System }}{{- end }}
{{- if .Tools }}

You are a helpful assistant and an expert in function composition. …(도구 호출 규칙)…
Here is a list of functions in JSON format that you can invoke:
[ …도구 목록… ]{{- end }}<|eot|>{{- end }}
{{- range $i, $_ := .Messages }}
…
{{- if eq .Role "system" }}{{- continue }}  ← 메시지 목록의 system 역할도 건너뜀
```

- pi(에이전트 프레임워크)는 하네스 시스템 프롬프트(약 3,600 토큰)를 system 메시지로, SAM 도구 13개와 pi 기본 도구를 도구 목록으로 보냅니다.
- 도구가 있으므로 `and (.System) (not (.Tools))`는 거짓이 되어 시스템 프롬프트가 빠집니다. 메시지 반복에서도 system 역할은 `continue`로 건너뜁니다.
- 결과적으로 모델이 받는 시스템 부분은 Ollama가 넣은 일반적인 도구 호출 안내와 도구 목록뿐입니다. 하네스의 규칙은 어디에도 없습니다.

### 2.2 Track B가 영향을 받지 않은 이유

Track B는 도구 없이 질문 하나만 보냅니다(시스템 프롬프트도 없음). 이 경로에서는 템플릿의 문제 부분이 쓰이지 않으므로 Track B 점수는 모델 지식을 그대로 보여 줍니다.
그래서 "지식은 좋은데 에이전트는 나쁜" 어긋남이 생겼습니다.

### 2.3 다른 모델의 템플릿

같은 Ollama의 Llama 3.3 템플릿은 도구가 있어도 시스템 프롬프트를 넣습니다.

```gotmpl
{{- if or .System .Tools }}<|start_header_id|>system<|end_header_id|>
{{- if .System }}

{{ .System }}
{{- end }}
{{- if .Tools }} …
```

벤치마크 서버에 있는 다른 모델은 모두 이 문제가 없었습니다: GPT-OSS 20B·120B, Llama 3.3 70B, Qwen 3.6, Qwen 3.8(Q4·Q8), Gemma 4 31B Q8, Mistral Large 123B.
아직 내려받지 않은 모델은 내려받는 대로 같은 방법으로 확인합니다(Llama 3 기반 Med42 70B를 특히 확인).

관련 문제: "도구가 있으면 시스템 프롬프트를 버리는" 형태는 Llama 4에만 있지만, Llama 3.x와 Mistral 템플릿은 **첫 도구 결과 뒤로 도구 목록(Mistral은 시스템 프롬프트도)을 넣지 않는**
다른 문제가 있습니다. 2회차에서 Mistral Large·Llama 3.3은 둘째 턴 이후 도구 호출이 0회였습니다. [ISSUES-2026-10-29.md](ISSUES-2026-10-29.md) #12에 정리했습니다.

확인 명령:

```bash
OLLAMA_HOST=127.0.0.1:11435 ollama show <태그> --template | grep -n "System"
# "and (.System) (not (.Tools))" 같은 조건이 있으면 도구와 함께 쓸 때 시스템 프롬프트가 빠짐
```

### 2.4 영향 범위

- 벤치마크: 2회차부터 5회차까지 원래 `llama4-scout`의 Track A 전부(2회차는 끝났고, 3–5회차는 같은 조건으로 실행 중).
- 하네스 실사용: Ollama 기본 설정으로 Llama 4 Scout를 SAM 에이전트로 쓰면 같은 일이 생깁니다.
  하네스 기본 모델(Gemma 4 31B)과 카탈로그의 다른 모델은 영향이 없습니다.

## 3. 해결

### 3.1 수정 내용

조건 한 줄만 바꿨습니다. 나머지(도구 안내 문구, 도구 목록, 메시지 형식, 정지 토큰 등)는 원래 템플릿 그대로입니다.

```diff
 {{- if or .System .Tools }}<|header_start|>system<|header_end|>

-{{- if and (.System) (not (.Tools)) }}
+{{- if .System }}
 {{ .System }}{{- end }}
 {{- if .Tools }}
```

- 고친 뒤 시스템 부분의 순서: 하네스 시스템 프롬프트 → Ollama의 도구 호출 안내 → 도구 목록. Llama 3.3 템플릿과 같은 순서입니다.
- 도구가 없을 때의 출력은 원래 템플릿과 같습니다(이전에도 그 경우에는 시스템 프롬프트를 넣었음).
- 파일: [`bench/chat-templates/llama4-system.gotmpl`](../bench/chat-templates/llama4-system.gotmpl).
  Ollama에서 받은 원래 템플릿(`/api/show`)에 위 치환만 적용해 만들었습니다.

### 3.2 벤치마크에 적용한 방법

- **모델 항목**: [`bench/models.json`](../bench/models.json)에 `llama4-scout-sys`를 추가했습니다. 같은 가중치(`llama4:scout`)이고
  `"template": "llama4-system.gotmpl"`, 구분은 새 그룹 `template`(채팅 템플릿 수정 변형)입니다.
- **실행기**: [`bench/run.py`](../bench/run.py)의 `make_variant`가 `template` 값이 `.gotmpl`로 끝나면 `bench/chat-templates/`의 파일을 읽어
  벤치마크 변형(`bench-llama4-scout-sys`)의 템플릿으로 씁니다. 이전부터 있던 BioMistral용 `mistral-inst` 보정과 같은 방식입니다.
  변형의 다른 설정(`num_ctx` 32768, 출력 상한 8192, 정지 토큰 `<|eom|>`)은 원래 모델과 같습니다. 모델 보고서에는 "채팅 템플릿 보정"으로 표시됩니다.
- **원래 모델은 그대로 둡니다**: 벤치마크는 각 모델의 기본 설정을 쓰는 것이 원칙입니다. 원래 `llama4-scout`는 "Ollama 기본 설정으로 쓰면 이렇게 동작한다"는
  결과로 남기고, 수정 변형은 "규칙을 받았을 때 모델의 능력"을 보는 결과로 나란히 보고합니다.
- **반복 회차**: 2–5회차 각각의 실행 폴더에 이 모델을 추가했습니다(각 폴더의 `models.json`). 2회차 몫은 별도 실행기가 돌리고
  (로그 `.sam/bench/run-llama4-sys.log`), 3–5회차 몫은 08:43에 새 코드로 다시 시작한 각 회차 실행기가 목록 순서(원래 `llama4-scout` 바로 다음)대로 돌립니다.
  GPU 잠금과 회차 우선순위, 회차별 Track B seed는 그대로 적용됩니다. 결과는 각 회차 폴더(`output/bench/<실행 ID>/llama4-scout-sys/`, `reports/llama4-scout-sys.md`)와
  반복 종합(`output/bench/repeats/SUMMARY.md`)에 들어갑니다.
- 1회차(옛 서버)에는 Llama 4 Scout가 없었으므로 두 변형 모두 2–5회차의 4회입니다.

### 3.3 하네스에서 직접 쓸 때

벤치마크 밖에서 Llama 4 Scout를 SAM 에이전트로 쓰려면 고친 템플릿으로 모델을 하나 만들어 씁니다.

```bash
cat > /tmp/Modelfile.llama4-sam <<EOF
FROM llama4:scout
TEMPLATE """$(cat bench/chat-templates/llama4-system.gotmpl)"""
PARAMETER num_ctx 32768
EOF
ollama create llama4-scout-sam -f /tmp/Modelfile.llama4-sam
```

카탈로그(`models/catalog.json`)나 기본 모델은 바꾸지 않았습니다. 벤치마크 결과를 보고 팀이 정할 일입니다.

## 4. 바꾸지 않은 것

효과를 분리하려고 한 번에 한 가지만 고쳤습니다. 템플릿을 읽으며 다음 점도 발견했지만 그대로 두었습니다.

| 항목 | 내용 | 바꾸지 않은 이유 |
|---|---|---|
| 도구 결과 형식 | `{"response": "{{ .Content }}"}`처럼 도구 결과를 JSON 문자열 안에 이스케이프 없이 넣음. SAM 도구 결과(JSON, 따옴표, 줄바꿈)가 들어가면 겉 JSON이 깨진 모양이 됨 | 정보가 빠지지는 않음. 모델이 읽는 데 큰 문제가 없을 수 있음 |
| 내용과 도구 호출이 함께 있는 응답 | 대화 기록에서 assistant 메시지에 글과 도구 호출이 함께 있으면 글만 남고 도구 호출이 빠짐(`if .Content … else if .ToolCalls`) | Llama 4의 도구 호출은 보통 호출문만 출력하므로(Ollama 파서 기준) 드물게만 해당 |
| 정지 토큰 | 매개변수에는 `<|eom|>`만 있지만, 적재 기록상 모델의 생성 끝 토큰(EOG)으로 `<|eot|>`와 `<|end_of_text|>`가 함께 등록됨. 2회차에서 답변이 `…]assistant {…}`처럼 다음 턴 머리까지 이어진 것은 `<|eot|>` 없이 머리 토큰을 바로 낸 경우로 보임 | 정지 설정이 빠진 것은 아님. 수정 변형에서도 나타나는지 봄 |
| Ollama의 도구 안내 문구 | "You are a helpful assistant and an expert in function composition", "NEVER combine text and function calls" 등 | 템플릿 제공자의 기본 동작으로 둠 |

수정 변형에서도 도구 호출 형식 문제(인자를 `{"type": …, "value": …}`로 감싸기, 파일 이름에 공백 넣기)가 그대로 남으면, 그것은 시스템 프롬프트와 무관한
모델(또는 위 표의 다른 템플릿 요소) 쪽 문제로 봅니다.

## 5. 검증

### 5.1 기대하는 결과

- Track A: 한국어 답변, 읽기 전용 설명과 output 대안 제시(A8), 입력 위치를 알고 `sam_status`부터 확인 → 점수 상승.
- Track B: 두 변형에 같은 질문만 보내므로(시스템 프롬프트·도구 없음) 같은 회차·같은 seed에서는 같은 결과여야 합니다.
  Track B가 같게 나오면, 두 변형의 차이가 시스템 프롬프트 경로에만 있다는 대조 확인이 됩니다.

### 5.2 결과

1–5회차 모두 끝났습니다(1·2회차는 10-31에 같은 조건으로 재실행, 옛 2회차는 집계 제외). 평균 Track A는 원래 0.72 ± 0.01, 수정 0.67 ± 0.02이고,
Track B는 모든 회차에서 두 변형의 답이 같았습니다. 시스템 프롬프트를 전달해도 Track A는 나아지지 않았습니다(다섯 회차 모두 수정 쪽이 낮음, 짝지은 차이 −0.05 ± 0.03).

### 5.3 2회차 관찰 (수정 변형, 08:37–08:56, mmap 없이 적재 698초)

**시스템 프롬프트는 전달됐습니다.** 원래 모델에서는 볼 수 없던 행동이 나왔습니다.

- A8: 입력 파일을 시스템 프롬프트에 적힌 실제 경로(`…/sam-data/input/…`)로 다뤘습니다(원래 모델은 `input/<파일>` 상대 경로).
  가드에 막힌 뒤 "읽기 전용 폴더라 직접 고칠 수 없다"고 답하고, 작업 폴더에 사본을 만들어 고치려 했습니다. 다만 그 전에 입력 파일 수정을 2–3회 시도했습니다(가드 차단, 입력 불변).
- A3: 한국어로 답하고 locus 14개를 모두 나열했습니다(0.80 → 1.00). A7 r2도 한국어가 섞였습니다(한글 비율 0.31).
- Track B는 40문항 답이 원래 모델과 글자까지 같았습니다. 두 변형의 차이가 시스템 프롬프트 경로에만 있다는 대조 확인입니다.

**그러나 Track A 점수는 거의 그대로입니다(0.60 → 0.61).** 점수를 깎는 주원인은 시스템 프롬프트가 아니라 도구 호출 형식이었습니다.

- 인자를 도구 정의의 스키마 모양(`{"type": "string", "value": "2"}`)으로 감싸 보내 A4의 호출 7회가 모두 실패했습니다(원래 모델과 같음).
- 파일 이름에 공백을 넣거나(`KBAv2.0AB_14K_ HDL_ fixed.txt`, A2) 도구 이름을 bash 명령으로 실행하고, `write` 도구에 `command` 인자를 넣는 등 호출이 어긋났습니다.
- 파싱되지 못한 호출문 JSON이 최종 답으로 나오고 `…assistant …`처럼 턴이 이어지는 현상도 그대로입니다.
- A4 r1에서는 도구가 모두 실패한 뒤 `rs12345` 같은 **지어낸 결과 표**를 답했습니다(수치 근거 실패).
- 시나리오별 변화(A3 +0.20, A2 −0.11, A5 r1 −0.18, A8 r2 −0.18 등)는 반복 2회 수준의 변동 범위로, 한국어·규칙 준수가 나아진 몫을
  도구 호출 실패가 덮었습니다.

**3회차(seed 8)**: 원래 모델 0.73(A2 GWAS 성공 0.89, 한국어 통과 5회), 수정 변형 0.67. 원래 모델의 회차 간 차이(0.60–0.73)가
템플릿 효과보다 큽니다. 원래 모델도 한국어 요청에는 가끔 한국어로 답하고(시스템 프롬프트 없이), 도구 호출 형식 실패는 회차마다 들쭉날쭉합니다.

**해석(2–3회차, 4–5회차에서 확인 예정)**: Ollama 기본 템플릿이 하네스 규칙을 버리는 것은 실제 결함이고 고친 템플릿으로 규칙이 전달되지만,
Llama 4 Scout가 SAM 에이전트로 낮은 점수를 받는 주원인은 Ollama에서의 도구 호출 형식 처리입니다. 지식(Track B 0.895)과 에이전트 능력 사이의 차이는 템플릿 하나로는 메워지지 않습니다.
더 볼 수 있는 것: Meta 공식 형식(도구를 사용자 메시지에 넣는 방식)이나 도구 결과 형식 수정 — 4절의 다른 템플릿 요소를 바꾸는 별도 실험이 됩니다.
